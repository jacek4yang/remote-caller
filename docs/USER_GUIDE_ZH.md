# iOS / Android Web App 使用指南

Remote Caller 是白名单双人通话 Web App。服务器管理员只配置固定账号；你和另一位用户使用不同账号，但进入相同 room 即可建立通话。

## 功能

- 语音或视频通话；
- 静音、摄像头开关、前后摄像头切换；
- 分享房间链接；
- 支持时保持屏幕唤醒与画中画；
- 信令断开指数退避重连；
- Wi-Fi/蜂窝网络变化时自动 ICE restart，必要时重建 PeerConnection；
- 房间严格最多两名连接。

## iPhone / iPad

建议使用最新版 Safari：

1. 通过 HTTPS 打开服务并登录。
2. 可用“分享 → 添加到主屏幕”安装为 PWA。
3. 首次进入通话允许麦克风/摄像头权限。
4. 没有声音时轻触页面一次，并检查系统音量、Safari 网站权限和输出设备。
5. 网络切换后给客户端数秒完成 ICE restart；持续失败再重新进入房间。

## Android

建议使用最新版 Chrome：

1. 通过 HTTPS 打开服务并登录。
2. 菜单中选择“安装应用”或“添加到主屏幕”。
3. 允许麦克风和摄像头权限。
4. 可使用翻转摄像头和设备支持的画中画。
5. 若系统允许，可为 PWA 放宽电池后台限制；这只能降低被系统暂停的概率，不能绕过 Chrome/Android 的后台策略。

## 发起通话

1. 登录自己的白名单账号。
2. 登录成功后会进入通话工作台；在这里选择视频或仅语音。
3. 发起方选择“生成房间号”，复制房间号或分享邀请链接，再进入房间等候。
4. 接收方把 6-64 位 URL-safe 房间号填入“加入房间”，也可以直接打开邀请链接登录后加入。
5. 双方使用不同账号进入同一个 room 即可开始通话；挂断后会回到工作台，不会退出账号。

房间链接不包含账号密码、JWT 或 TURN credential；拿到链接的人仍然必须拥有服务器白名单账号。

## 长时间通话

前台页面保持运行、网络正常时，服务按数小时连续通话设计：WebSocket 有主动心跳，TURN credential 不会在通话中途因为伪 TTL 突然失效，信令和 ICE 也有恢复逻辑。

但是浏览器平台存在硬限制：

| 场景 | Android Chrome/PWA | iOS Safari/PWA |
|---|---|---|
| 前台数小时通话 | 支持，仍取决于设备/网络 | 支持，仍取决于设备/网络 |
| 短暂切到其他 App | 通常可短暂保持音频，视频可能受限 | 可能较快暂停采集/网络 |
| Wi-Fi ↔ 蜂窝切换 | 自动尝试 ICE restart | 自动尝试 ICE restart |
| 锁屏长期持续 WebRTC | 不保证 | 不保证，限制通常更严格 |
| 回到前台 | 自动尝试恢复 | 自动尝试恢复 |
| 系统级来电通知 | 不支持 | 不支持 |

如果需要锁屏后仍像普通电话一样长期通话、系统来电 UI、PushKit/CallKit 或 Android ConnectionService，需要原生客户端；Web 服务端无法解除操作系统限制。

## 隐私与安全

- 密码只以 Argon2id 哈希形式配置在服务器；
- JWT 只保存在当前页面内存，不写入 `localStorage`；本地只记住用户名；
- JWT 不进入 WebSocket URL，WebSocket 使用短时一次性 ticket；
- TURN credential 由服务器高熵 secret 针对白名单账号派生；不是账号登录密码；
- 媒体使用 WebRTC DTLS-SRTP，优先 P2P；需要时经服务器 TURN 中继；
- 服务不录制音视频；
- 点击挂断会停止本机媒体轨道。
